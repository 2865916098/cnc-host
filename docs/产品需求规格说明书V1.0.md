## 第一章 项目总体目标

### 1.1 项目定位

本项目不是简单的机床监控 APP，也不是只负责发送 G 代码的软件，而是一套面向真实生产环境的两轴数控车床智能上位机。

操作人员上传零件图纸后，软件尽可能自动完成：
- 图纸导入和格式识别
- 零件轮廓提取
- 尺寸识别和几何校验
- 材料、毛坯和刀具信息匹配
- 切削工艺参数推荐
- 粗车和精车刀路生成
- 刀路二维仿真
- 行程、过切和已建模碰撞风险检查
- 加工前检查清单生成
- 操作工审核与确认
- 自动送料、夹紧、切削、退刀和松料
- 加工过程监控
- 暂停、故障处理和符合条件的断点恢复
- 加工结果、报警和日志保存

软件的原则是：尽量自动处理常规工作，但不能在关键加工条件不明确时擅自猜测，更不能绕过人工审核和设备安全条件。

### 1.2 已知项目条件

- 控制卡型号尚未确定，暂时没有完整通讯协议
- 开发电脑为 Windows
- 已有普通 Android 平板
- 设备为 X/Z 两轴数控车床
- 控制卡负责底层伺服脉冲、实时插补及其支持的硬件同步功能
- 上位机负责工艺规划、刀路数据生成、任务管理、指令下发、IO 流程调度和设备监控
- 必须支持无真实设备时的模拟开发
- 真实设备接入后，必须根据实际控制卡协议完成适配和验证

控制卡尚未确定不应阻止 UI、图纸解析、CAM、仿真、任务管理和模拟控制系统的开发。

### 1.3 项目成功标准

项目不能以"页面已完成"作为交付标准。至少需要满足：
- 能在目标 Android 平板上安装和运行
- 能导入有效 DXF 并正确解析已支持的几何实体
- 能对图纸单位、轮廓和尺寸进行校验
- 能根据明确的毛坯、刀具和材料条件生成受支持的车削刀路
- 仿真使用与执行任务相同版本的刀路数据
- 能在模拟控制卡环境下完整运行加工流程
- 能检测模拟的通讯中断、夹紧失败、超时和设备报警
- 能保存任务、配置、日志和审核记录
- 真实设备未接入时明确显示模拟模式，不得伪装成真实连接
- 控制卡接入后，只有完成协议验证、设备联调和安全验收的功能才允许投入生产

## 第二章 产品架构与技术路线

### 2.1 推荐架构

采用 Android 原生应用作为主体，业务模块清晰分层。推荐技术：
- **Kotlin**：主要开发语言
- **Jetpack Compose**：Android 界面开发
- **MVVM**：页面与业务状态管理
- **Kotlin Coroutines**：异步任务处理
- **Room**：本地结构化数据存储
- **DataStore**：普通应用设置
- **Android USB Host API**：USB 串口设备接入基础能力
- **TCP Socket**：网络通讯
- **2D Canvas 或自定义绘图组件**：刀路预览和仿真
- **独立几何计算模块**：轮廓处理和刀路算法
- **独立协议适配层**：隔离不同控制卡的通讯差异
- **自动化测试框架**：单元测试、集成测试和端到端测试

具体第三方库由 Trae 调研后确定，必须记录许可证、维护情况、Android 兼容性和使用限制。

不得把所有功能写进一个 Activity 或一个超大 ViewModel。

### 2.2 建议模块划分

- **app 模块**：负责应用入口、导航、主题、页面装配和 Android 生命周期
- **core-model 模块**：保存零件、图纸、刀具、毛坯、工艺、刀路、任务、报警和设备状态等统一数据模型
- **drawing 模块**：负责 DXF、矢量 PDF、栅格图像的导入和解析
- **geometry 模块**：负责几何计算、坐标转换、轮廓闭合检查、相交检查和几何约束
- **recognition 模块**：负责图片预处理、OCR、尺寸标注识别、比例校正和识别置信度管理
- **cam 模块**：负责工艺规划、粗车、精车、进退刀、刀具补偿策略和刀路校验
- **simulation 模块**：负责刀路绘制、轨迹播放、单步调试和已支持的风险检测
- **device-api 模块**：定义设备连接、命令发送、状态读取、报警查询和 IO 访问接口
- **device-simulator 模块**：模拟控制卡、运动状态、IO 反馈、设备报警和故障场景
- **device-serial 模块**：实现 USB 串口通讯适配
- **device-tcp 模块**：实现 TCP 通讯适配
- **automation 模块**：负责送料、夹紧、切削、退刀、松料等流程状态机
- **task-engine 模块**：负责任务状态、命令队列、执行进度、暂停和恢复资格判断
- **storage 模块**：负责本地数据库、任务持久化、配置版本和数据迁移
- **logging 模块**：负责通讯日志、运行日志、报警记录和诊断导出
- **settings 模块**：负责设备配置、材料库、刀具库、权限和系统设置

### 2.3 统一业务数据流

图纸文件 → 图纸解析 → 几何模型 → 尺寸校验 → 零件与毛坯定义 → 材料与刀具选择 → 工艺方案 → 刀路模型 → 刀路校验 → 仿真 → 人工审核 → 设备就绪检查 → 加工任务 → 命令执行与反馈 → 生产记录。

所有模块必须共享明确的数据模型和版本信息，不允许每个页面各自保存互不关联的数据。

## 第三章 Android 工业 UI 设计规范

### 3.1 总体视觉风格

采用现代工业 HMI 风格。设计方向：
- 深石墨色背景
- 深灰色面板
- 高对比度文字
- 蓝色用于一般操作和信息
- 绿色用于经过确认的正常状态
- 黄色用于警告和需要注意的状态
- 红色用于报警和危险状态
- 禁用状态使用低对比度灰色，但必须仍然能够看清原因
- 统一图标、间距、边框、字体、按钮高度和弹窗样式

不能将所有状态简单地用颜色区分，还必须配合文字、图标和明确的状态说明。

### 3.2 横屏布局

建议采用三段式布局：
- 左侧导航栏：约占可用宽度的 15%
- 中央工作区：约占 60%
- 右侧状态面板或任务操作区：约占 25%

具体比例根据实际平板分辨率调整。顶部状态栏始终显示：软件名称和版本、设备名称、连接状态、当前模式、当前任务状态、当前报警摘要。重要加工操作应在加工页面内保持容易找到。

### 3.3 统一交互规范

所有页面必须具备统一的：加载状态、空数据状态、失败提示、连接中断提示、权限不足提示、参数校验提示、保存成功或失败反馈、操作确认窗口、未保存数据提示。

禁止使用没有业务逻辑的装饰按钮。每个按钮都必须实现实际动作，或明确标注尚未实现且不可用于生产。

### 3.4 模式标识

软件必须明确区分：离线模式、模拟设备模式、真实设备已连接模式、真实设备故障模式。模拟模式下的轴位置、主轴反馈、IO 状态和加工结果必须标注为模拟数据。模拟模式与真实设备模式必须有明确边界，不能仅通过一个普通开关就绕过设备识别和安全检查。

## 第四章 全部页面详细需求

### 4.1 首页与设备总览

显示：设备名称、通讯方式、当前连接状态、X 轴实际位置、Z 轴实际位置、目标位置、主轴状态和设备支持的反馈信息、当前刀具、当前工件、当前任务、任务执行步骤、任务进度、IO 摘要、最新报警、通讯状态、最近加工任务、今日真实加工记录摘要。

提供入口：新建加工任务、导入图纸、图纸管理、工艺管理、刀路仿真、加工控制、IO 监控、报警中心、设备配置、系统设置。不得在没有生产记录时显示伪造的生产统计。

### 4.2 图纸管理页面

支持：DXF、矢量 PDF、JPG、PNG、扫描版 PDF。

页面包含：文件名、格式、大小、导入时间、图纸预览、解析状态、识别置信度、尺寸校验结果、图纸版本、对应零件编号、重新解析、复制版本、导出、删除。

删除已关联加工任务的图纸时，必须进行引用检查，避免破坏历史记录。

### 4.3 图纸解析与尺寸校正页面

采用左右分栏。左侧显示原始图纸，右侧显示解析轮廓。

支持：缩放和平移、图层显示控制、选择加工轮廓、选择或排除实体、设置单位、设置坐标原点、设置 X 轴方向、设置 Z 轴方向、设置直径模式或半径模式、修改识别尺寸、标注缺失尺寸、查看识别来源、查看无法解析的实体、检查轮廓是否闭合、检查自相交、检查不合理的几何关系。

每个关键尺寸必须标注来源：原始矢量实体、OCR 识别、几何推断、人工修改。图像识别不能无条件覆盖矢量图纸数据。对于比例不明、单位不明或关键尺寸冲突的图纸，必须要求用户确认。

### 4.4 零件与毛坯设置页面

允许配置：零件名称、零件编号、图纸版本、材料、毛坯直径、毛坯长度、装夹方式、夹持长度、工件零点、加工余量、禁止加工区域、关键公差、成品轮廓。所有涉及真实工件装夹和机床坐标的信息，都必须来源明确并经过确认。

### 4.5 材料库

支持：新增材料、修改材料、复制材料、禁用材料、导入和导出、参数版本管理、参数来源记录。每种材料可配置推荐切削速度、进给范围、切深范围和适用刀具等信息。推荐值必须具有可追溯来源和适用条件。

### 4.6 刀具库

每把刀具至少记录：刀具编号、刀具类型、刀尖半径、刀具方向、刀片几何信息、刀杆尺寸、适用材料、适用工序、推荐参数范围、磨损状态、参数来源、使用记录。刀具几何、刀具方向和补偿定义必须与 CAM 算法约定一致。

### 4.7 工艺规划页面

提供自动推荐和手动编辑两种模式。自动推荐考虑：材料、毛坯尺寸、成品轮廓、刀具能力、机床能力、粗车策略、精车策略、切削速度、主轴转速、进给、每层切深、精车余量、进退刀距离、安全距离、预计加工时间。

参数必须经过范围校验。当材料、刀具或机床能力未知时，不允许凭空生成看似精确的生产参数。方案可以保存、复制、比较和重新应用。

### 4.8 CAM 刀路生成页面

支持：粗车分层切削、精车轨迹、安全进刀、安全退刀、轮廓方向分析、过切风险检查、未加工区域检查、轴行程检查、毛坯和成品轮廓检查、刀具补偿策略、刀路版本管理、生成报告、重新计算、比较不同版本。

不支持的几何特征必须明确提示。软件不得将普通二维轮廓算法直接当作完整的三维碰撞检测系统。

### 4.9 刀路仿真页面

显示：坐标轴、刻度、毛坯、成品轮廓、刀具轨迹、进退刀路径、当前刀具位置、当前轨迹段、运动方向、粗车与精车分类、风险区域。

交互包括：播放、暂停、单步、复位、播放速度调节、缩放、平移、适配视图、轨迹段选择、坐标查询、轨迹列表查看。

仿真必须使用与最终加工任务相同的刀路版本。修改工艺参数或设备配置后，必须使依赖旧参数的刀路和审核结果失效。

### 4.10 加工审核页面

每次启动真实加工前，必须检查：图纸版本已确认、关键尺寸已确认、毛坯已确认、材料已确认、刀具已确认、工艺参数有效、刀路生成成功、仿真已完成、轴行程检查通过、已支持的过切检查通过、设备型号与配置一致、单位和坐标定义一致、设备就绪、必要的夹紧反馈正常、IO 配置有效、必要的硬件安全条件满足。

每项必须有明确状态和失败原因。最终启动需要操作人员主动确认。审核通过不代表软件可以取代物理安全防护和机床安全联锁。

### 4.11 加工主控页面

显示：任务编号、当前工序、当前轨迹段、当前刀具、X/Z 实际位置、X/Z 目标位置、主轴状态、当前进给状态、IO 状态、运行时间、预计剩余时间、任务进度、最新设备反馈、通讯状态、最新报警。

操作：开始任务、暂停、受控停止、符合条件时恢复、终止任务、查看刀路、查看报警、查看日志。

紧急停止功能不能只依靠 Android 软件按钮实现，必须由符合设备安全要求的硬件安全回路或安全系统承担。

### 4.12 IO 监控页面

显示全部输入和输出：点位编号、点位名称、输入或输出方向、当前状态、最近变化时间、是否为关键反馈、相关自动化步骤、当前异常状态。

支持配置 IO 映射和流程关联。手动 IO 操作必须有权限控制、互锁检查和确认机制。模拟模式可以测试 IO 流程，但模拟结果不能代替真实电气联调。

### 4.13 通讯配置页面

支持：USB 串口、TCP、串口参数、设备地址、端口、数据帧格式、校验方式、超时、心跳、ACK、重试、断线重连、消息队列、日志级别、协议版本。

控制卡协议未确定时，先实现统一接口、模拟协议和协议配置框架。不得假定不同控制卡使用相同指令格式。

### 4.14 设备配置页面

支持：X/Z 轴行程、单位、坐标方向、直径或半径模式、工件零点、速度和加速度限制、软限位、主轴能力、IO 映射、设备协议、配置版本、配置锁定、配置导入导出。安全相关参数修改后，必须重新校验受影响的加工任务。

### 4.15 报警中心

显示：报警代码、报警来源、报警内容、发生时间、当前设备状态、相关任务、处理建议、是否允许确认、是否允许恢复。确认报警不等于故障已经消除。恢复前必须重新验证设备状态。

### 4.16 任务历史与生产记录

记录：任务 ID、图纸版本、工艺版本、刀路版本、刀具、毛坯、审核记录、开始和结束时间、执行结果、报警、中止原因、恢复记录、最终状态。支持按日期、零件、状态和任务编号查询，并导出记录。

### 4.17 系统设置与权限

至少包含：普通操作工、设备管理员。权限范围包括：普通任务操作、工艺参数修改、设备参数修改、IO 调试、通讯配置、报警确认、配置导入导出。权限系统不能替代硬件安全保护。

## 第五章 图纸解析与几何处理

### 5.1 DXF 解析

优先支持常见二维实体：LINE、ARC、CIRCLE、LWPOLYLINE、POLYLINE、SPLINE（在实现能力经过验证后支持）。

解析时必须考虑：图层、单位、坐标变换、圆弧方向、多段线闭合属性、重复实体、辅助线、标注实体、不支持的实体类型。不得直接假设图纸中的所有实体都是加工轮廓。

### 5.2 PDF 处理

对于矢量 PDF，尽量提取矢量路径和文本。对于扫描版 PDF，转换成图像后进入识别流程。两种路径必须有明确区分。

### 5.3 图片与 OCR

建议流程：
- 图像方向校正
- 去噪
- 对比度增强
- 图纸区域定位
- 尺寸文字识别
- 几何轮廓提取
- 比例校正
- 尺寸与几何约束匹配
- 置信度评估
- 人工确认

不能仅凭 OCR 识别出一个数字，就认为该尺寸与对应几何关系已经正确建立。图片识别应作为辅助方案。高精度加工优先使用可信的矢量图纸和明确的尺寸约束。

## 第六章 CAM 与刀路数据设计

### 6.1 内部刀路模型

建议建立与具体控制卡无关的统一刀路模型。每个轨迹段至少包含：段 ID、运动类型、起点坐标、终点坐标、圆弧中心或半径等必要参数、进给策略、工序类型、刀具信息、安全属性、关联的工艺参数、校验结果。

支持的运动类型应根据算法实现能力确定，例如快速定位、直线进给和圆弧运动。

### 6.2 粗车算法

必须根据毛坯和成品轮廓生成分层切削路径。需要处理：切削方向、切深限制、粗车余量、轮廓边界、安全进刀、退刀、不可达区域、刀具几何约束。

### 6.3 精车算法

精车轨迹必须基于最终轮廓及刀具补偿约定生成。需要考虑：成品轮廓、精车余量、刀尖半径、刀具方向、轮廓转角、进退刀方式、公差要求。不支持的复杂轮廓必须报告，而不能静默生成错误轨迹。

### 6.4 行程和过切检查

至少检查：轨迹坐标是否超出配置的轴行程、是否存在非法坐标、是否出现异常跳变、是否存在几何过切、是否存在已建模的毛坯碰撞风险、是否缺少必要的进退刀段。碰撞检测能力必须在文档中明确说明覆盖的几何对象。

## 第七章 自动化加工状态机

### 7.1 推荐流程

待机 → 任务加载 → 参数校验 → 设备就绪检查 → 人工审核 → 启动许可检查 → 送料 → 送料反馈确认 → 夹紧 → 夹紧反馈确认 → 必要的主轴准备 → 粗车 → 精车 → 退刀 → 停止或按流程控制主轴 → 松料 → 松料反馈确认 → 加工结果记录 → 返回待机。具体工序顺序必须由实际机床结构、送料装置和控制卡能力确定。

### 7.2 每个状态必须具备

- 进入条件
- 执行动作
- 完成条件
- 超时处理
- 错误处理
- 退出条件
- 是否允许重试
- 是否允许恢复
- 关联日志

不能依靠固定延时判断送料或夹紧已经完成。优先使用真实反馈信号判断动作结果。

### 7.3 暂停

暂停请求必须由任务状态机处理。软件需要确认控制卡支持何种暂停方式，并区分：不再下发新的运动命令、请求控制卡受控暂停、当前运动完成后暂停、设备侧暂停确认。不能仅仅隐藏运行界面或停止发送消息，就宣称机床已经停止。

### 7.4 断点恢复

恢复前必须检查：设备连接正常、设备无未解除的报警、真实轴位置已重新读取、夹紧状态正确、主轴状态符合要求、当前任务与设备状态一致、断点位置有效、当前刀路版本未改变、IO 状态符合恢复要求。

无法确认设备状态时，必须阻止自动恢复。不能只保存一个刀路行号，就认为具备安全的断点续跑能力。

### 7.5 紧急停止

必须区分：APP 发起的受控停止、控制卡提供的停止指令、符合设备安全要求的硬件急停。APP 不能取代硬件急停回路。如果硬件急停已经触发，APP 不得通过普通软件操作绕过或复位该安全条件。

## 第八章 通讯与控制卡适配

### 8.1 统一设备接口

设计统一设备接口，至少包含：connect、disconnect、getConnectionState、readStatus、readAxisPositions、sendMotionCommand、requestPause、requestStop、readInputs、setOutputs、readAlarm、queryCommandResult。这些是内部接口设计建议，不代表真实控制卡已经支持对应指令。

### 8.2 命令队列

命令必须包含：命令 ID、任务 ID、命令类型、参数、发送时间、超时时间、当前状态、设备确认信息、错误信息。

建议命令状态：创建 → 已入队 → 已发送 → 已确认 → 执行中 → 已完成。异常状态包括：发送失败、超时、设备拒绝、执行失败、执行结果未知。对于执行结果未知的运动命令，禁止盲目重复发送，必须先查询设备状态或执行规定的恢复程序。

### 8.3 USB 串口

实现时必须处理：USB Host 权限、设备插拔、串口参数、收发缓冲、帧解析、数据校验、超时、断线重连、日志。具体 USB 转串口芯片、驱动和协议必须根据实际设备验证。

### 8.4 TCP

实现时必须处理：连接超时、断线检测、心跳、数据帧边界、半包和粘包、消息确认、断线重连、网络异常时的任务状态管理。TCP 连接成功不代表设备已经准备好加工。

## 第九章 数据管理和版本控制

### 9.1 核心数据对象

至少包括：DrawingDocument、GeometryModel、PartDefinition、StockDefinition、MaterialDefinition、ToolDefinition、ProcessPlan、Toolpath、MachineProfile、ProtocolProfile、IoMapping、AutomationRecipe、ProductionTask、DeviceSnapshot、AlarmRecord、OperationLog。

### 9.2 版本一致性

每个加工任务必须绑定：图纸版本、几何版本、工艺版本、刀路版本、刀具配置版本、设备配置版本、IO 流程版本。依赖参数改变后，旧的刀路校验和审核结果必须失效。历史任务应保留当时使用的配置快照，便于追溯。

### 9.3 本地离线运行

图纸解析、CAM、仿真、任务管理和日志应尽量在本地运行。如某项 OCR 功能需要联网，必须明确告知用户，并提供适当的离线处理方案。

## 第十三章 主要风险与应对

**风险一：控制卡协议未知**
应对：先实现模拟器、统一设备接口和协议适配框架，等待真实资料后接入。

**风险二：图纸识别错误**
应对：保留尺寸来源、置信度和人工确认；关键尺寸不明确时阻止进入加工审核。

**风险三：CAM 生成错误刀路**
应对：建立独立几何测试、过切检查、行程检查和仿真；不支持的几何必须明确报告。

**风险四：自动化 IO 时序错误**
应对：采用状态机、反馈确认、超时和互锁，不使用未经验证的固定延时作为完成依据。

**风险五：通讯中断后重复执行命令**
应对：为命令分配 ID，记录执行状态，区分失败和结果未知，先核对设备状态再决定是否恢复。

**风险六：Android 后台运行或进程被回收**
应对：持久化任务状态，明确设备侧执行状态和 APP 状态的区别，重启后重新核对设备，不能盲目继续。

**风险七：软件停止不等于硬件急停**
应对：保留硬件急停、安全联锁和设备侧保护。APP 仅承担符合设备能力的控制与监控功能。
