# ADR-0001 控制卡驱动注册表与配置化接入

- 状态：已采纳（已实现，提交 `8a2119a`）
- 日期：2026-10-29
- 决策者：用户（「兼容所有控制卡，仅需后台配置」；授权先做市面主流卡）

## 背景

控制卡型号未定，但系统必须面向「未来接入任意控制卡」设计。若按单一型号硬编码对接，换卡即需改客户端并发版，现场成本不可接受。

## 决策

1. `DeviceController` 接口**冻结不变**，作为所有驱动的统一契约。
2. device-api 引入**驱动注册表**：`DeviceDriverFactory` / `DeviceDriverRegistry` / `DriverConnectionParams`。驱动类型（`driverType`）+ 键值参数（`params`）全部由服务端后台下发。
3. 首个真实驱动为**通用 Modbus TCP**（新模块 device-modbus）：覆盖网口控制卡主流形态；寄存器地址、缩放、位定义全部由后台 `params` 配置（见 `ModbusRegisterMap`），接入新卡只改后台配置。
4. app 端 `DeviceRepository` 按同步配置经注册表选驱动；**未知驱动、参数非法、创建失败一律安全回退内置模拟器**，绝不因后台配置错误导致无设备可用。
5. 固高 GT/GTS 等 PC-based 卡（市占第一）不走平板直连，后续经工控机网关路径接入，网关侧同样可复用本注册表。

## 备选方案

- A. 每款控制卡一个硬编码适配类：换卡需发版，否决。
- B. 服务端统一代理控制卡协议：平板→服务端→控制卡，断网即停加工，违背离线铁律，否决。
- C. 选定唯一型号：型号未定且违背用户目标，否决。

## 后果

- 正面：新增控制卡 = 新增驱动模块 + 后台配置；客户端零改动；离线能力不受影响（驱动在平板本地直连控制卡）。
- 代价：通用驱动的寄存器映射是「约定布局」，接入具体厂商卡时需按厂商协议文档在后台核对映射；命令语义不同的卡需扩展驱动而非仅调参数。
- 约束：真实卡联调前，驱动正确性仅由假传输单测保证；P8 现场验收必须包含真机运动安全验证。
