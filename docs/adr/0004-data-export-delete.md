# ADR-0004 数据永久保留 + 删除/导出 API

- 状态：已采纳
- 日期：2026-10-29
- 决策者：用户（「永久保留，提供删除和导出」）

## 背景

规范 §6 要求客户数据有明确保留与删除策略。用户决策：**默认永久保留**，同时必须提供主动的删除与导出能力（覆盖设备激活信息、任务记录、操作日志）。

## 决策

1. **不设置自动过期/清理任务**；所有业务数据默认永久保留。
2. 新增管理端 API（需 ADMIN 以上权限 + 操作审计记录）：
   - `GET /api/v1/admin/export?scope=<devices|tasks|logs>&from=&to=` → JSON/CSV 导出，按租户 + 时间范围过滤。
   - `DELETE /api/v1/admin/data?scope=<...>&from=&to=&confirm=<phrase>` → 删除指定范围数据；必须二次确认（请求体携带确认短语），删除动作写操作日志。
3. 删除为**硬删除**（物理删除），并保证：删除后该范围数据不再出现在任何查询/导出结果中。
4. 导出文件不出服务端目录，由管理后台触发下载；私有化部署下不离开局域网。
5. 设备激活信息（单位/联系人/电话）纳入 `devices` 导出/删除范围。

## 备选方案

- A. 软删除（deleted 标记）：保留期语义与「永久保留+主动删除」不符，且查询路径全部要加过滤，否决。
- B. 定期自动清理：与「永久保留」直接冲突，否决。

## 后果

- 正面：满足合规「可删除、可导出」；默认零数据损失风险。
- 代价：库体积单调增长——接受（加工数据量级小）；删除接口属高危操作，必须二次确认 + 审计。
- 验证：导出内容完整性测试；删除后查询不可见测试；无确认短语删除被拒测试；删除动作入审计日志测试。
