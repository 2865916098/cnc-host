# ADR-0005 APK 签名验签与仅联网更新

- 状态：已采纳
- 日期：2026-10-29
- 决策者：用户（「发布签名密钥由超级管理员分发、只有 app 连上网络了才能更新」）

## 背景

现状（R4）：APK 更新仅校验 SHA-256 摘要，无签名校验——若服务端或传输被攻破，恶意 APK 可直达平板。规范 §11.2 强制签名验证。

## 决策

1. **密钥保管**：发布签名私钥由超级管理员**离线保管**（不进仓库、不进服务端、不进 CI 产物）；公钥（签名证书 SHA-256 指纹）**内置客户端**作为验根。
2. **验签点**：客户端下载 APK 后、调起安装前，用 `PackageManager` 读取 APK 签名证书指纹，与内置白名单比对；不一致即拒绝安装并删除安装包。SHA-256 完整性校验保留（防传输损坏）。
3. **仅联网更新**：更新检查、下载、安装引导全部要求在线；不提供离线更新包通道。
4. **服务端发布**：发布接口记录版本、SHA-256、最低兼容版本；签名由发布者本地完成后再上传（服务端不接触私钥）。
5. 渠道/灰度/回滚本期不做，列入后续阶段；当前所有设备同渠道。

## 备选方案

- A. 服务端持私钥自动签名：私钥暴露面大，违背用户「超管分发」决策，否决。
- B. 每次发布新密钥对 + 服务端下发公钥：下发链路本身需信任锚，循环依赖，否决。
- C. 仅 SHA-256 校验：无法防服务端被攻破后的恶意替换，否决。

## 后果

- 正面：恶意 APK 无法通过客户端验签；私钥暴露面最小（超管离线保管）。
- 代价：密钥丢失 = 无法发布可升级的新包（需现场重装）；接受，由超管承担保管责任并在管理手册中写明。
- 验证：指纹匹配通过 / 不匹配拒绝 / 无签名 APK 拒绝 / 正常升级回归。
